A class exhibits Type Checking (also known as the "Switch Statements" or "Conditional Complexity" smell) when its behavior is repeatedly selected by testing an object's type or a "type code" field, rather than by polymorphic dispatch. Two shapes of this smell are detected:

  • The same enum-typed field is used as the selector of a switch statement in several methods of the class — every new case requires touching every one of those switches.
  • An if / else if chain tests the same variable with instanceof across three or more branches — every new subtype requires adding another branch here (and everywhere else the same chain is duplicated).

Both are resolved with Replace Conditional with Polymorphism (create a subclass per case, move each branch's logic into an overriding method) or, when the "type" represents changing state rather than a fixed hierarchy, Replace Type Code with State/Strategy.

Noncompliant Code Example

class Bird {

  enum Type { EUROPEAN, AFRICAN, NORWEGIAN_BLUE }

  private Type type;

  double getSpeed() {
    switch (type) {
      case EUROPEAN:
        return getBaseSpeed();
      case AFRICAN:
        return getBaseSpeed() - getLoadFactor() * numberOfCoconuts;
      case NORWEGIAN_BLUE:
        return isNailed ? 0 : getBaseSpeed(voltage);
    }
    throw new IllegalStateException();
  }

  String getPlumageDescription() {
    switch (type) {
      case EUROPEAN:
        return "blue and white";
      case AFRICAN:
        return "unladen";
      case NORWEGIAN_BLUE:
        return "beautiful plumage";
    }
    throw new IllegalStateException();
  }
}

Compliant Solution

abstract class Bird {
  abstract double getSpeed();
  abstract String getPlumageDescription();
}

class European extends Bird {
  double getSpeed() { return getBaseSpeed(); }
  String getPlumageDescription() { return "blue and white"; }
}

class African extends Bird {
  double getSpeed() { return getBaseSpeed() - getLoadFactor() * numberOfCoconuts; }
  String getPlumageDescription() { return "unladen"; }
}

class NorwegianBlue extends Bird {
  double getSpeed() { return isNailed ? 0 : getBaseSpeed(voltage); }
  String getPlumageDescription() { return "beautiful plumage"; }
}

Limitations

  • Only enum-typed fields are treated as "type codes" for the switch detector. int/String type codes are not currently matched (extend fieldSelector in the check to widen this).
  • The instanceof-chain detector requires the same variable to be tested in every branch of a single if/else-if chain; instanceof checks scattered across unrelated statements aren't correlated.
  • This rule flags a candidate for polymorphic refactoring. It does not verify the branches actually share a meaningful abstraction — that judgment remains the developer's.
  • Unlike JDeodorant, this rule does not rank refactoring opportunities by their impact on design, and does not apply the refactoring automatically — it only reports the smell.
